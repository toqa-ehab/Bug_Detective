# 📖 Project Overview

**Bug Detective** is an AI-powered debugging assistant for Python. You paste code that crashes, and it investigates the bug the way a developer would:

1. **Runs** the code and captures the traceback.
2. **Diagnoses** the bug (type, severity, line, root cause) using an LLM.
3. **Reproduces** it by generating a unit test that proves the bug exists.
4. **Fixes** it by proposing corrected code.
5. **Verifies** the fix by running the fixed code and a generated regression test.

The result is a clear pass/fail report, so you can see not only *what* the model thinks is wrong, but whether its fix actually holds up when it is run.

The project has two parts:

- **Backend:** a Kaggle notebook that loads `Mistral-Nemo-Instruct-2407`, runs the pipeline, and exposes it as a FastAPI service through an ngrok tunnel.
- **Frontend:** a single-file web UI (`index.html`) that sends code to the API and shows the results step by step.

---

# ✨ Features

* **Full debugging pipeline:** run, diagnose, reproduce, fix, and verify in one request.
* **LLM-generated tests:** every fix is checked by a reproduction test and a regression test, not just by the model's word.
* **Structured output:** all model answers are validated against Pydantic schemas, with one automatic retry if the JSON is malformed.
* **Clear web UI:** step tracker, highlighted crash line, diagnosis card, side-by-side diff of the fix, and copy/export buttons.
* **Safe execution limits:** code runs in a separate process with a 10-second timeout, so infinite loops cannot freeze the server.
* **API key protection:** the `/debug` endpoint rejects requests without the correct `X-API-Key` header.
* **Demo mode and history:** try the UI without a server, and revisit the last 10 investigations.

# ⚙️ Installation

## 1. Backend (Kaggle notebook)

1. Upload `bug-detective.ipynb` to [Kaggle](https://www.kaggle.com/) and open it.
2. In **Session options**, set the **Accelerator** to **GPU T4 x2** and turn **Internet** on.
   The 12B model needs about 24 GB of GPU memory in fp16. On a single T4, load it in 4-bit instead (see *Future Improvements*).
3. Create a free account at [ngrok.com](https://ngrok.com/) and copy your authtoken.
4. In **Add-ons → Secrets**, add two secrets and tick both so they are attached to the notebook:
   - `NGROK_TOKEN`: your ngrok authtoken.
   - `BUG_API_KEY`: a long random string you make up (generate it outside the notebook).
5. Run all cells. The last setup cell prints a public URL like `https://xxxx.ngrok-free.dev`.

## 2. Frontend

No installation is needed. Open `index.html` in a browser.

> The ngrok URL changes every time the notebook restarts (free plan), so paste the new one into the UI each session.

# 🚀 Usage

1. Open `index.html`.
2. Paste the ngrok URL into the address box in the header, and your `BUG_API_KEY` value into the **API key** box. The dot turns green and says **Connected**.
3. Paste Python code that crashes, or pick one of the built-in samples.
4. Click **Investigate** (or press Ctrl+Enter). A run takes about a minute.
5. Read the results:
   - **Banner and step tracker:** whether everything passed.
   - **Original run:** the crash, with the failing line highlighted.
   - **Diagnosis:** bug type, severity, root cause, and explanation.
   - **Fix:** a diff of the changes, with copy buttons.
   - **Reproduction and regression tests:** the generated tests and their results.

Always read the fix before using it. A green result means the fixed code runs and the model's own tests passed, not that the fix matches your intent.

### API

```http
POST /debug
X-API-Key: <your key>
Content-Type: application/json

{ "code": "def f(x):\n    return 1 / x\n\nprint(f(0))" }
```

Returns `status`, `original_execution`, `bug_report`, `reproduction_test`, `reproduction_execution`, `fix_report`, `fixed_execution`, `regression_test`, `regression_execution`, and `verification_passed`. `GET /health` returns `{"ok": true}`.

# 📈 Results

- **Division by zero:** all five stages passed. The crash was found, diagnosed as `ZeroDivisionError`, reproduced by a test, fixed with an empty-list guard, and confirmed by a regression test.
- **KeyError:** the crash was caught and the failing line was highlighted correctly.
- **Class with a type error:** the bug was diagnosed and the fix passed its regression test, but the generated reproduction test failed. The tool reported this honestly as "fix needs a look" instead of claiming success.
- **Syntax errors:** detected up front and reported without calling the model.

Two engineering lessons from building it:

- Instruct models need their **chat template**, and greedy decoding makes JSON output far more reliable.
- Model-written test files often define things in the wrong order, so the pipeline **rebuilds each test script itself** (real source first, test body next, runner last) instead of trusting the model's layout.

---

# ⚠️ Limitations

- Works best on **short, self-contained Python scripts that crash** with a runtime error.
- Code that runs without crashing but returns wrong results is **not** detected.
- Code that needs `input()`, files, network access, or extra libraries may fail for unrelated reasons.
- The model can choose a fix that silences the error but changes behavior. A human should review every fix.
- Code is executed with a timeout but **not in a real sandbox**. Keep the API key private and never expose the endpoint publicly without it.
- Requests are handled one at a time, and each takes around a minute.

# 🔮 Future Improvements

* Run submitted code inside a real sandbox (for example Docker with no network access).
* Show real progress per step (streaming or job polling) instead of a timer-based tracker.
* Add 4-bit quantized loading so the project runs on a single T4 GPU.
* Detect logic bugs in code that does not crash, using generated test cases.
* Support multi-file projects and other programming languages.
* Host the backend permanently, so the URL no longer changes.
